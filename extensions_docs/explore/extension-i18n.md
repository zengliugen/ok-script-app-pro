## 要解决的问题

具体现象或缺口。不要写「想加个功能」——那句话通常意味着问题还没界定。

- 现象：框架的 `ok` 翻译域目录（`i18n/<locale>/LC_MESSAGES/ok.po`）是**上游文件**，
  扩展能力如果新增界面可见文案（任务名、Tab 名、配置键与选项），只能改这个上游目录才能翻译，
  而改它会在 `git merge upstream/master` 时产生冲突，且上游已把那 27 条 OCR 相关条目写进去，
  扩展条目混进去后无法区分归属。

- 不做的后果：扩展能力的界面文案会一直是英文原文或中文硬编码；要么不做本地化，
  要么每次改动都去动上游文件并登记 `divergence.yaml`。两条路都会随能力增多而恶化。

## 已确认的决定

每轮提问与回答的落点。每行一条决定，必须写清「凭什么这么定」——
理由缺失的决定，等于把问题原样推给后来者。

| 决定 | 为什么这么定 | 成立前提 |
|---|---|---|
| 用「扩展自有域 + fallback 挂载」而不是「新增语言基础码目录」 | 自有域可以覆盖上游译文、域隔离不会撞车；语言基础码目录（`i18n/en/`）只能追加不能覆盖，且 `zh_TW` 的回退链会把扩展译文给到繁体用户 | 框架的 `App.po_translation` 在 `my_app` 创建前为 `None` 且懒加载（已核实 `ok/__init__.py:318/324/351`） |
| 域名用 `ok_ext` | 与上游 `ok` 域完全隔离；框架本身已有多域先例（`ok` 与 `ocr`，`ok/core/translation.py:88/94`） | 无 |
| `.po` 与 `.mo` 都入库 | 与上游 `i18n/` 的做法一致；构建链不需要新增编译步骤（实测 `pyappify.yml` 与 workflows 均无 `msgfmt`/`polib`） | 译文改动会产生二进制 diff，靠 `check-mo` 保证两者一致 |
| 译文按能力包落位：`capabilities/<能力>/i18n/` | 与规则的「能力自包含」一致；删能力时译文随之删除，不留孤儿条目 | 加载器需遍历各能力包目录 |
| 配置键沿用上游 Title Case 名词短语，只把 ASCII / 下划线语义 / 三处对齐做成机械检查 | 键名同时是界面标签（`LabelAndWidget(key, desc)`），命令式命名会先暴露原始键名；「命令式」无法脚本判定，写进规则只会变成无人执行的建议 | 无 |
| 编译与校验不依赖 `polib` | 实测 `.venv` 未安装 `polib`，技能的 `compile`/`check` 均退出 3；门禁要在任何机器与 CI 上稳定运行 | 自写的 `.mo` 写出已被 `gettext.GNUTranslations` 实测可解析 |

## 已排除

考虑过但明确不做的方向，以及在什么前提下它会重新变得正确。
只写「不行」会让后来者无法判断当初的否决是否仍然成立。

| 方向 | 排除理由 | 重新可行的前提 |
|---|---|---|
| 直接在 `i18n/<locale>/LC_MESSAGES/ok.po` 里加上游条目 | 该目录是上游文件，改动会在 `git merge upstream/master` 时冲突，且必须逐条登记 `divergence.yaml` | 项目不再跟进上游时 |
| 新增语言基础码目录 `i18n/en/`、`i18n/zh/` 存放扩展译文 | 只能追加不能覆盖；`zh_TW` 的回退链是 `['zh_TW','zh']`，会把简体扩展译文给繁体用户 | 只在「无需覆盖上游、且不介意繁体行为」时可用 |
| 扩展直接 `monkey patch` `get_translations` | 路径 1/3 已能解决（`my_app` 钩子 + 预置 `po_translation`），patch 属最后手段 | 框架移除 `po_translation` 这一注入点时 |
| 把「命令式英文命名」写进配置键规则 | 无法机械判定；且与上游既有键风格相反 | 有办法静态识别语义时 |

## 结论

一句话说清做什么、不做什么。**结论为空时不允许建立能力文档**——那意味着还没有确认任何东西。

- 做：新增 `extension-i18n` 能力，用自有 `ok_ext` 域 + fallback 挂载接管翻译链；
  译文按能力包落位、`.po` 与 `.mo` 均入库；同时把 i18n 技能改为零依赖、作用域扩到
  `extensions/`，并把本地化要求接进体检与提交门禁。

- 不做：不改上游 `i18n/` 目录、不新增语言基础码目录、不 patch 框架翻译函数、
  不为配置键引入命令式命名规则。
