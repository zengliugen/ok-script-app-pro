## #1 改道判据从「非最小化」收紧为「最大化且未最小化」

| 字段 | 值 |
|---|---|
| 日期 | 2026-11-04 |
| 类型 | 更优路径 |

**触发场景**：实现「安全版置前」时，设计文档写的是「只在 `IsIconic()` 为真时才 `SW_RESTORE`」，
即普通窗口也跳过系统调用。写代码时按这条实现，等于把普通窗口的置前也自己重写了一遍。

**原计划**：`_needs_native_restore_skipped` 只在窗口最小化时返回 False（交回上游），
其余（最大化 + 普通窗口）都走自建置前。

**实际做法**：判据改为「`isMaximized() and not isMinimized()` 时改道」，普通窗口一律交回上游实现 `original()`。

**原因**：自建置前只保留了置前的四个 Qt 调用与两个 Win32 调用，但上游实现日后若在这个方法里
增加别的行为（例如按平台分支处理焦点、托盘还原、初次显示特殊处理），普通窗口会因改道而
**静默丢失**这些行为。把改道范围收窄到「确实会因 `SW_RESTORE` 坏掉」的那一类，语义边界最小、
与上游的分歧面最小——只有最大化窗口的置前是本能力自建的，其余一律跟随上游。

**影响**：
- 计划批次一受影响（判据调整），批次二至四不受影响。
- 新风险：无。普通窗口行为回到完全由上游控制，与安装本能力前一致。
- 不需要新写决策记录：这是实现期的范围收窄，不推翻设计结论（设计文档「为什么只对最大化窗口
  改道」一节已就地改写为现在的判据）。
