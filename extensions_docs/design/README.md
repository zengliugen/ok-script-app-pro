# design/ —— 设计文档

## 放什么

- 新扩展能力的**方案推演**：要解决什么问题、有哪些候选做法、各自代价
- 候选方案之间的**比较与取舍理由**：为什么选 A 不选 B，B 在什么前提下反而更合适
- 已有的**实测证据**：验证某个假设时跑的命令与结果（可复现，便于日后复核）

## 不放什么

| 内容 | 应去哪 |
|---|---|
| 已拍板的决策结论 | `decisions/`——决策一旦定稿就不可变，不能随方案文档一起被改写 |
| 实施步骤与进度 | `plans/` |
| 强制约束（目录职责、禁止项） | 规则文件 `project-extension-capability/layout.mdc` |
| 对已实现代码的复述 | 不写。代码本身是事实来源 |

## 命名

`<能力名>.md`，与能力总览表的「能力」列一致。一个能力一份设计文档，不按章节拆文件。

## 完成判据

方案已被决策记录采纳后，本文档状态改为「已实施」，保留在原处不迁移——
后续若要重审该能力，从这里读到的正是当初的完整推理。
