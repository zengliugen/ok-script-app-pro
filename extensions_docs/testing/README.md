# testing/ —— 测试策略与验收记录

## 放什么

| 内容 | 说明 |
|---|---|
| 测试策略 | 哪些行为必须覆盖、为什么；哪些行为刻意不测 |
| 验收记录 | 某能力上线时跑了什么、结论如何、当时的环境 |
| 已知盲区 | 测不到的行为及原因（如依赖真实设备、依赖图形环境） |

## 不放什么

**用例代码只存在于 `extensions_tests/`，本目录只引用文件名与方法名，不复制用例内容。**
用例是可执行事实，文档是判断依据；文档抄用例必然在代码改动后漂移。

引用写法：

```markdown
覆盖 `extensions_tests/TestExtensions.py::TestExtensionOverrides.test_apply_raises_on_missing_key`
```

## 必须区分两类测试

项目有两组测试根，结论不可混用：

| 测试根 | 通过意味着 | 通过**不**意味着 |
|---|---|---|
| `tests/` | 上游既有行为未被破坏 | 扩展按预期工作 |
| `extensions_tests/` | 扩展自身按预期工作 | 上游行为完好 |

写验收记录时必须标明依据的是哪一组。文档里出现「测试全绿」而不指明测试根，等于没写。

## 命名

`<能力名>-testing.md`，与能力总览表对应。
