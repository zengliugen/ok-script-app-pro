## 测试策略

| 被测行为 | 为什么必须覆盖 | 对应用例 |
|---|---|---|
| 最大化且未最小化的窗口不走上游实现 | 上游实现无条件发 `SW_RESTORE`，走到它就会被降级——这是本能力存在的唯一原因 | `test_maximized_window_bypasses_original` |
| 最大化分支仍执行 Qt 侧置前动作 | 只删系统调用而忘记置前，窗口会「看起来正常但不置前」，用户以为启动没反应 | `test_maximized_branch_keeps_foreground_calls` |
| 最小化后的窗口交回上游 | 最小化确实需要 `SW_RESTORE`；若也被改道，最小化的窗口永远拉不回来 | `test_minimized_window_defers_to_original` |
| 普通窗口交回上游 | 收窄改道范围（见偏差 #1）；回归时能发现「改道范围被误扩大」 | `test_normal_window_defers_to_original` |
| 替换后保留原实现引用 | 便于排查与回退；也证明替换不是就地覆盖 | `test_replaces_bring_to_front` |
| 重复调用不叠加包装 | 语言切换会重建主窗口并再次触发钩子，叠加包装会让一次置前执行多次 | `test_protect_is_idempotent` |
| 目标缺失时立即崩溃并指名 | 上游改名/删除该方法后，静默跳过会让缺陷以「偶发界面错乱」形式回归 | `test_missing_target_raises`、`test_non_callable_target_raises` |
| 真实 `MainWindow` 上方法存在 | 替身层只能证明代码符合我们对上游的假设，契约层才证明假设本身仍成立 | `test_main_window_provides_bring_to_front` |

**刻意不测的行为**：

| 行为 | 不测的原因 |
|---|---|
| 真实窗口的双标题栏/客户区内缩是否消失 | 需要真实窗口与系统合成器，无法在 unittest 中稳定断言；已改为一次性的真实启动验证（见下「验收记录」的补充验证） |
| `SetForegroundWindow` 是否成功抢到前台 | 结果取决于 Windows 前台锁与当前焦点窗口，不可确定；且失败不阻断启动（与上游一致） |
| DPI 变化与系统吸附加后的框架重算 | 本能力明确不做（方案 B/C，见探索记录「已排除」），测它等于测未实现的行为 |

> **必须写明依据的是哪个测试根。** 框架基线与自有代码两类测试的结论不可互换：
> 自有代码全绿不能证明框架行为完好，框架基线全绿也不能证明自有代码正确。
>
> 本次未运行 `tests/`（上游基线）：改动只落在 `extensions/` 与 `extensions_tests/`，
> 未触碰上游文件；上游基线是否完好与本能力无因果关系，不能作为本能力验收依据。

**用例数必须填**：测试因缺少依赖而整类跳过时，框架往往仍返回成功——全部跳过与全部通过，退出码可能相同。

## 已知盲区

| 盲区 | 影响面 | 缓解手段 |
|---|---|---|
| 双标题栏是否消失只能在真实启动中用截图判断 | 单元测试无法覆盖，回归时不会被 CI 捕获 | 本文档记录了修复前后的窗口矩形差异（客户区是否等于窗口），可作人工复核判据 |
| 多显示器、非 100% 缩放下未实测 | 本次环境为单屏 2560x1440 @100% | `WM_NCCALCSIZE` 的内缩值由框架按 DPI 计算，本能力不参与该计算；若在高 DPI 下复现同类问题，按探索记录「重新可行前提」启动自愈守卫方案 |
| 上游 `bring_to_front` 若改变签名或语义 | 替换实现可能不再等价 | 契约测试守住「方法存在」；语义变化只能靠升级上游时人工比对 |
