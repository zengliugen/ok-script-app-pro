# archive/ —— 已完成能力归档

## 放什么

已完成能力的文档整包归档：该能力的 design、plan、deviation、testing 四份文档随能力目录一起移入。

```
archive/
└── <能力名>/
    ├── design.md
    ├── plan.md
    ├── deviation.md
    └── testing.md
```

活跃区与归档区**同构**（都是「一能力一目录 + 固定文件名」），因此归档是一次目录搬迁，
不需要改名；四份文档的文件名与在活跃区时完全一致，引用它们的相对路径只需替换前缀。

## 为什么不删除

归档的价值不是保存结论（结论已进代码与规则），而是保存**当时不知道什么**。
半年后要判断「这个能力能不能改」时，知道当初有哪些盲区、哪些方案被排除过，比知道最终选了什么更有用。

## 与 decisions/ 的边界

ADR **不进归档**，永远留在 `decisions/`。原因：决策链靠编号顺序连续，移动会打断追溯。

## 归档动作

1. 该能力在 `README.md` 能力总览表的状态改为「已归档」，各列指向 `archive/<能力名>/` 下的文件
2. 活跃目录中的文件移入 `archive/<能力名>/`
3. 不要删除归档内容
