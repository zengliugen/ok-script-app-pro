# archive/ —— 已完成能力归档

## 放什么

已完成能力的文档整包归档：该能力的 design、plans（plan + deviation）、testing 全部文档移入该目录。

```
archive/
└── <能力名>/
    ├── design.md
    ├── plan.md
    ├── deviation.md
    └── testing.md
```

也可以把活跃目录里的原文件**直接按原名移入**，不必重命名——保持文件名与原始路径的对应关系，便于回查。

## 为什么不删除

归档的价值不是保存结论（结论已进代码与规则），而是保存**当时不知道什么**。
半年后要判断「这个能力能不能改」时，知道当初有哪些盲区、哪些方案被排除过，比知道最终选了什么更有用。

## 与 decisions/ 的边界

ADR **不进归档**，永远留在 `decisions/`。原因：决策链靠编号顺序连续，移动会打断追溯。

## 归档动作

1. 该能力在 `README.md` 能力总览表的状态改为「已归档」，各列指向 `archive/<能力名>/` 下的文件
2. 活跃目录中的文件移入 `archive/<能力名>/`
3. 不要删除归档内容
