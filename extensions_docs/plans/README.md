# plans/ —— 实施计划与偏差记录

## 两种文件

| 文件 | 内容 | 生命周期 |
|---|---|---|
| `<能力>-plan.md` | 分批任务、文件清单、验收标准 | 开工前写定；实施中只在**重大转向**时回写一句并指向偏差条目 |
| `<能力>-deviation.md` | 实施偏差：触发场景、原计划、实际做法、原因、影响 | 实施期间持续追加，按时间倒序 |

**为什么拆成两个文件**：主计划若同时承载流水账，会变得无法快速回答「原计划是什么」。
偏差独立成文后，主计划保持可读，过程记录也无需为了不干扰主线而被压缩掉。

## 偏差记录的准入

只有当「实际做法 ≠ 计划」时才写。典型触发场景：

- 实测证明原计划的技术前提不成立（如某个 API 行为与文档不符）
- 发现更简单的路径，绕开了原计划的一批任务
- 范围扩张或收缩（新增了一个原本没打算做的子任务）

不写的内容：日常调试过程、与计划一致的正常推进、纯代码细节调整。

## 命名

统一后缀，一个能力恰好一对：

```
plans/config-overrides-plan.md
plans/config-overrides-deviation.md
```

## 归档

能力完成后整对移入 `archive/<能力名>/`，不删除。
