# 输出风险画像（project-ok-script-codegen）

## 风险矩阵

| 风险类别 | 严重度 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|---|
| 编造 API 或参数名 | 高 | 中 | 生成的代码运行即报 `TypeError`／`AttributeError` | 规则写明「不要编造 API」；落地前用目标解释器核实方法存在；API 参考标注依据版本 |
| 编造模板名 | 高 | 中 | 代码引用不存在的模板，运行时匹配恒失败 | 明确要求「除非用户给出，否则假定没有模板」；用 `*_template` 占位名并注明需手动标注 |
| 循环里不取新帧 | 高 | 中 | 第二轮起读到同一张旧图，检测结果恒定，表现为「一直点不到」 | 模板与 `references/frame-and-wait.md` 都给出「不取帧」的失效对照 |
| 到处加 sleep | 中 | 高 | 任务总时长无谓拉长，超时语义偏移 | 规则区分「等状态用 wait_」与「动作延迟才补 sleep」 |
| 循环里判 `exit_is_set()` | 中 | 中 | 与框架的中断路径不一致，停止响应延迟 | 明确禁止，并解释 `sleep` 抛异常即结束任务 |
| 用相对坐标替代可稳定识别的元素 | 中 | 中 | 分辨率或布局变化后点偏 | 要求「有稳定文字或图标时优先 OCR／模板」，坐标仅作退路 |
| 声称坐标精确 | 低 | 中 | 用户按「精确」预期使用，实际有偏差 | 要求用谨慎措辞「根据截图估算」 |

## 输出质量维度

### 代码可运行

- 只用 ok-script 公开 API 与目标项目既有 API。
- 非必要不引入 OpenCV 或其他外部库。
- 不写「看起来合理但没人验证过」的参数组合。

### 注释合规（本项目硬约束）

- 每个非空行都有行内中文注释，控制流与 import 也不例外。
- 注释说意图，不复述语法。
- 涉及估算的坐标在注释里标明估算来源。

### 边界清晰

- 只产出 `run(self)` 方法体，不顺手生成任务类骨架与注册行。
- 用户没给模板名时不假装存在；用户没给截图时不编造坐标。

## 已知局限性

1. **静态推断的天然上限**：截图为二维图像，无法判断元素是否会动态出现、是否有动画过渡，
   这些只能靠用户补充或后续调参。
2. **无法验证真实匹配效果**：模板阈值、OCR 区域是否合适，需要实际运行观察。
3. **API 依据单一版本**：参考 `ok-script 2.0.0b7`。库升级后签名变化不会自动报错。
4. **不承担语义审查**：生成结果的稳定性、性能、可维护性不由本技能保证；
   需要审查时走 `project-python` 相关审查链路。
5. **注释密度是显式取舍**：逐行注释会让代码变长，这是本项目为可读性主动选择的代价，
   在追求紧凑的场景应说明并降级为段落注释。
