# 帧生命周期与等待方法

本文件解释 codegen 规则里「帧刷新」那几条的成因。改生成代码前先读这一份，
否则容易写出「能跑但一直点不到东西」的实现。

## 一、帧不是实时画面

`self.frame` 是**一帧快照**，不是「随取随新的当前画面」。检测类 API（`ocr`、`find_one`、
`find_feature`）默认都读这一帧。所以：

- 界面已经变了但帧没换 → 检测结果还是旧界面的；
- 这不会报错，表现是「明明在界面上却一直返回空」。

## 二、什么动作会清帧

源码依据：`TaskExecutor.sleep()` 开头调 `self.reset_scene(check_enabled=False)`，
即 sleep 本身就把场景（含帧）重置掉。

| 动作 | 是否清帧 | 说明 |
|------|---------|------|
| `self.sleep(t)` | 是 | 经 `reset_scene` 清掉，下一轮检测自然取新帧 |
| `self.next_frame()` | 是 | 清帧并立即取一帧新的 |
| `click(..., after_sleep=t)` | 是 | 点击后等待并清帧 |
| `click_relative(..., after_sleep=t)` | 是 | 同上 |
| `click_box(..., after_sleep=t)` | 是 | 同上 |
| `wait_click_ocr(..., after_sleep=t)` | 是 | 同上 |
| `ocr` / `find_one` / `find_feature` | 否 | 只读当前帧 |

结论：**任何改变界面的动作之后都可能需要重新取帧**，否则下一次检测仍在看旧画面。

## 三、`wait_` 与 `find_` / `ocr` 的取舍

`wait_ocr`、`wait_click_ocr`、`wait_feature`、`wait_click_feature` 内部已经是
「取帧 → 检测 → 不命中则重试」的循环，直到超时或命中。

| 场景 | 该用什么 |
|------|---------|
| 等某个界面出现 | `wait_ocr` / `wait_feature` |
| 等出现并点击 | `wait_click_ocr` / `wait_click_feature` |
| 已经在循环里，每轮自己控制节奏 | `ocr` / `find_one` |
| 需要多步组合判断（如「A 出现且 B 不出现」） | 一次 `ocr` 后本地判断 |

两条推论：

1. **`wait_` 前面不要加多余 `sleep`**——它自己会重试，多睡的这段时间纯属浪费，
   且会让超时时间变得不可预期。
2. **循环里用 `find_`/`ocr` 就必须每轮取新帧**，否则第二轮开始读的是同一张旧图。

## 四、循环的正确写法

```python
while True:  # 持续轮询，直到命中或用户停止
    box = self.ocr(match="确认")  # 读当前帧做识别
    if box:  # 命中则点击并跳出
        self.click_box(box, after_sleep=0.5)  # 点击后等待界面刷新
        break  # 结束循环
    self.sleep(0.5)  # 未命中时等待并清帧，同时响应停止请求
```

三个关键点：

- **不要写 `self.exit_is_set()`**。用户手动停止任务时 `sleep` 会抛异常结束任务，
  自己判退出既多余，又会漏掉这条中断路径。
- **`sleep` 必须有**。没有它就会变成不带间隔的死循环，CPU 占满且不响应停止。
- **睡眠放在循环末尾而不是开头**，避免第一轮白等一次。

## 五、什么时候该额外补 sleep

`wait_` 已经覆盖了「等状态」；额外 sleep 只用于**动作触发的延迟**：

- 点击后播放动画、转场，界面要过一会儿才稳定；
- 触发了异步加载（网络请求、资源解压）；
- 已知某界面有固定延迟才刷新。

这时用带 `after_sleep` 的点击，或点击后 `self.sleep(0.5)`。
不要为了「保险」到处加 sleep——每次额外 sleep 都在拉长任务总时长，且掩盖真实问题。

## 六、常见错误与现象对照

| 写法 | 现象 |
|------|------|
| 循环里只用 `ocr` 不取帧 | 第二轮起永远读到第一帧，检测结果恒定 |
| 点击后立刻 `ocr` | 读到点击前的旧画面，误判「点了没反应」 |
| `wait_ocr` 前面加 `sleep(2)` | 任务变慢，超时语义偏移，真的超时时多等 2 秒 |
| 循环里判 `self.exit_is_set()` | 用户停止后要等到下一轮判断才退出，且与框架的中断路径不一致 |
| 用 `find_one` 当作「等待」 | 找不到就立刻返回，不会重试，等价于只检查一次 |
