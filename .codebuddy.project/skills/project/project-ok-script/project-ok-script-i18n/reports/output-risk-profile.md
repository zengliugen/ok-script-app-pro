# 输出风险画像（project-ok-script-i18n）

## 风险矩阵

| 风险类别 | 严重度 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|---|
| 改了 `.po` 忘记编译 `.mo` | 高 | 高 | 翻译不生效，排查方向会被误引向「代码没调 tr」 | SKILL.md 工作流最后一步即编译；`references/catalog-rules.md` 单列一节说明成因 |
| `msgid` 与源串有不可见差异 | 高 | 中 | 该条目静默失效，界面显示源串 | 要求从代码复制原文；给出全角半角、空格的对照表 |
| 只补了部分语言目录 | 中 | 高 | 某些语言仍显示源串 | 工作流要求「逐语言检查」，并以目录实际枚举为准 |
| 硬编码语言清单 | 中 | 中 | 新增语言被漏掉 | 明确「列 `i18n/*/LC_MESSAGES/ok.po`，不写死语言清单」 |
| 重排整个文件 | 中 | 中 | diff 变成整文件改写，无法评审真正改动 | 规则要求新条目追加到末尾 |
| 顺手改了 Python 里的配置键 | 高 | 低 | 用户持久化配置全部失效 | 明确配置键保持稳定，翻译目录只影响显示 |
| 缺 `polib` 时静默跳过编译 | 高 | 低 | 同上第一条，且更隐蔽 | 脚本以退出码 3 报错并给安装命令，不静默跳过 |
| 翻译纯日志串 | 低 | 中 | 维护面扩大，日志反而更难检索 | 规则默认不翻日志串，除非用户明确要求 |

## 输出质量维度

### 编译产物一致

- 每个改动过的 `.po` 都有对应的新 `.mo`。
- 改动摘要里同时列出 `.po` 与 `.mo`，避免只提交一半。

### 译文可用

- 界面文案简洁，不逐词直译。
- 占位符、代码要求的标点、热键名保持原样。
- 简体与繁体分开处理，不混用字形。

### 扫描结果不被过度信任

- 扫描器基于 AST，只覆盖字面量常量。
- 输出清单是**下限**，动态拼接的文案必须人工补。
- 每个扫描结论都应回到任务文件核对一遍。

## 已知局限性

1. **无法判断译文质量**：语法上合法、语义上生硬或术语不一致，脚本查不出来。
2. **动态文案盲区**：f-string、经常量拼接、从配置读取的文案，静态分析看不到，
   也不会有固定 `msgid` 与之对应。
3. **语言回退由框架决定**：只建 `zh_CN` 时繁体用户会回退到 `zh` 或源串，
   这不是本技能能改变的行为，只能提示补目录。
4. **`polib` 是外部依赖**：不在项目运行依赖中，可能缺失；缺失时按环境不可用处理。
5. **不做翻译记忆**：同一串在不同任务里出现时手工保持一致，脚本不做冲突检测。
