# 输出风险画像（project-ok-script-tasks）

## 风险矩阵

| 风险类别 | 严重度 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|---|
| 编造不存在的 API | 高 | 中 | 生成的代码 import 或调用失败，用户以为是用法问题 | SKILL.md 明确「不要编造 API」；`references/task-api.md` 标注依据版本 2.0.0b7，落地前要求用目标解释器核实 |
| 元数据写在 `super().__init__` 之前 | 中 | 中 | 任务名、配置被父类初始化覆盖，界面显示类名而非预期名 | 必备规则第一条即「先调父类」；模板注释在 `super()` 行标注原因 |
| `config_type` 键不在 `default_config` 里 | 中 | 中 | 控件不渲染，用户以为配置没生效 | 模板与检查清单各写一次「每个 config_type 键都必须同时出现在 default_config」 |
| 触发任务过度轮询 | 中 | 中 | CPU 占用高、日志刷屏 | 要求显式设置 `trigger_interval`，并说明 0 与 5 的语义差异 |
| 触发任务返回真值语义用错 | 中 | 低 | 执行器反复从头扫描，其他触发任务被饿死 | 规则写明「只有确实做了应让高优先级任务重跑的动作才返回真值」 |
| 直接继承 `BaseTask` 绕过项目基类 | 中 | 中 | 丢掉项目公共初始化（图标、日志、场景绑定等） | 工作流第 1 步要求先读项目现有基类并优先继承 |
| 配置键被写成中文或随文案改动 | 中 | 低 | 用户旧配置失效（键是持久化 JSON 字段名） | 规则要求键保持稳定英文，中文说明走 `config_description` |

## 与其他技能的边界风险

本技能与 `project-ok-script-codegen`、`project-ok-script-i18n` 的产出物相邻，容易互相越界：

| 越界形态 | 表现 | 处置 |
|---|---|---|
| 把 `run()` 的完整动作序列写进任务骨架 | 与 codegen 的产出重复，两处改一处漏一处 | 骨架只留「观察 → 判断 → 调用」的小步骤，具体动作交 codegen |
| 顺手改 `.po` 条目 | 与 i18n 技能的编译步骤脱节，改了不生效 | 只提示「需要翻译」，不要动翻译目录 |
| 顺手打 tag | 与 release 技能的版本号规则冲突 | 发布一律交 `project-ok-script-release` |

## 输出质量维度

### 代码可运行性

- 优先用目标项目里已存在的类与辅助方法，不引入新依赖。
- 每个用户可改的设置都在 `default_config` 里，读取一律 `self.config.get(...)`。
- 设备相关代码无法本地验证时明确说明「未在真机验证」。

### 说明与代码分离

- 用户只要代码时不附长篇解释。
- 用户要解释时，先给代码再给说明，避免正文淹没代码。

## 已知局限性

1. **依据单一库版本**：`references/task-api.md` 依据 ok-script 2.0.0b7。库升级后字段增删
   不会自动报错，需要人工核对。
2. **不判断需求合理性**：本技能不评估「这个任务该不该做」「这个功能有没有价值」，
   只负责把已有设计落成任务类。
3. **无脚本自动化验证**：本技能不含可执行脚本，全部结论靠读代码与项目约定，
   因此「是否继承项目基类」「注册位置是否正确」依赖人工确认。
4. **模板示例用英文键名**：示例中的类名与配置键保持英文，直接照抄到中文项目里时
   需要按项目风格调整 `name` 与 `description` 的文案。
