# 输出风险画像

> 本文件由人工撰写（非工具生成）。当前技能**没有脚本单元测试**，本文件是主要的自我约束记录。

## 风险矩阵

| 风险 | 触发场景 | 表现 | 缓解 |
|---|---|---|---|
| **静默通过** | 表格解析或字段正则失效 | 输出「零缺口」，退出码 0——看起来一切正常 | 输出必须含「项目根」与结论行；零缺口时人工抽查一个已知约束 |
| 误报堆积 | 规则调整后脚本未同步 | 每次 audit 都报同一条不存在的问题 | 出现重复误报时先查脚本是否落后于规则，而不是加豁免 |
| `new` 污染文档 | 能力名合法但与既有能力语义重复 | 生成一套永远填不满的骨架 | 生成后立即检查总览表新增行是否合理；重复的骨架手工删除 |
| 插入位置错误 | 总览表结构被人改动 | 新行插到表外或破坏表结构 | 插入前校验表头；定位失败时回滚已生成文件 |
| ADR 编号误判 | 目录里混入非 ADR 的 .md | 报文件名不合规 | 只匹配 `NNNN-<slug>.md`，README 排除；其余 .md 视为违规并提示 |

## 输出的三类质量问题

### 1. 结论与明细不一致

退出码由最高档决定（有错误即 2），但输出可能同时含错误与警告。
**读者容易只看最后一行「结论」，忽略上面的错误明细**——尤其当错误只有一条时。

缓解：错误分组始终排在警告与提示之前，且每组带计数。

### 2. 「提示」被当成「没问题」

提示级（如「代码变了但总览表未变」）不改变退出码，容易被忽略。
但它往往正是「新能力未登记」的唯一信号。

缓解：提示单独成组输出，不隐藏在通过分支里。

### 3. 路径信息不足以定位

缺口消息必须带**相对项目根的完整路径**（如 `extensions_docs/design/foo.md`），
不能只说「design/foo.md 缺字段」——后者在读代码时无法判断是哪个目录。

## 自查清单（改动脚本后必看）

| 项 | 检查方式 |
|---|---|
| 能正常跑 | `python <脚本> audit` 无 traceback |
| 全绿时输出干净 | 无缺口时只打印标题与结论，不打印空分组 |
| 非法输入被拒 | `new 中文名` 报错并给示例，退出码 2 |
| 重名被拒 | 对已存在的能力名执行 `new`，退出码 2，不写文件 |
| 缺参数被拒 | `new` 不带参数，退出码 2 |
| 表头被改能识别 | 手工改一列表头，audit 报「表头契约」错误 |
| 指向不存在的文件能识别 | 表里填 `design/ghost.md`，audit 报错 |
| 缺 `__init__.py` 能识别 | 在 `extensions/` 下建空目录，audit 报错 |

## 已知盲区

| 盲区 | 影响 | 为什么不修 |
|---|---|---|
| 不检查文档**内容**质量 | 写了但写的是废话，audit 判通过 | 内容质量无法机械判定 |
| 不检查 ADR 正文是否被改写 | 已提交的 ADR 被修改不会被发现 | 需要 git 历史基线；当前文档体系尚未提交，基线不存在。提交后可加此项 |
| 不检查 plan 与代码的一致性 | 计划写 A 实现成 B 不报错 | 需要语义理解 |
| 不校验能力名与实际代码的对应 | `new foo` 之后再没写任何代码也不报错 | 无法判断「代码里哪部分是 foo 能力」 |

## 免责声明

本技能的退出码**只能证明「机械检查通过」，不能证明「文档合格」**。
零缺口意味着没有违反结构约束，不意味着设计写得对、取舍有依据。
