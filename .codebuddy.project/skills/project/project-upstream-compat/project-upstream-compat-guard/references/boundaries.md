# 边界、环境依赖与降级表现

本技能刻意做窄。以下每条都是「不做」，且不做是有理由的。

## 不做的事

| 不做 | 理由 | 该谁做 |
|---|---|---|
| `git fetch` / `git merge` / 任何同步动作 | 高风险 git 操作不应藏在技能脚本里，出问题难追溯 | 规则 `upstream-sync.mdc` 的人工流程 |
| 判断某个改动「该不该改上游文件」 | 需要读 diff 与理解业务，脚本只做机械比对 | 人（或模型）读 diff 后决定 |
| 推断 `reason` 并写进清单 | 自动生成的原因半年后毫无价值，且会被当成真实结论 | 人写动机；`--add` 只给骨架 |
| 自动修改 `divergence.yaml` | 校验工具改被校验对象，会掩盖问题 | 人补登记 |
| 断言「上游行为未被破坏」 | 登记完整 ≠ 行为正确，两件事无关 | 跑 `tests/` 上游基线；`extensions_tests/` 通过不算此证据 |
| 分析差异的语义（谁改了哪一行、为什么） | 输出会爆炸且不可判定 | `git diff` / `git log` |

## 环境依赖

- **Python 3.8+**，仅用标准库 + `PyYAML`。
- **PyYAML 缺失**时导入即 `ModuleNotFoundError`，报错里不含修复提示。
  遇到时执行 `pip install pyyaml`；若需长期免装，改成读 JSON 需同步改规则侧字段定义，不建议。
- **必须在 git 仓库内、且项目根可上溯**。脚本自 `__file__` 向上查找含 `.codebuddy` 的目录
  作为项目根（`resolve_project_root`），**不依赖脚本所在的层数**，因此技能收进族目录后仍能正确定位。
  但**不能把脚本复制到项目树之外执行**——上溯不到 `.codebuddy` 会直接抛 `RuntimeError`。
- **Windows / Linux / macOS 均可**。路径统一 `replace("\\", "/")` 后再比对，
  与 YAML 里的正斜杠一致；不做大小写归一（git 本身在大小写不敏感文件系统上已处理）。

## 已知的判定盲区

| 盲区 | 表现 | 缓解 |
|---|---|---|
| 只看树差异，不看内容 | 文件被改回原样后仍显示 `M`（空差异会被 git 吸收，故实际少见） | 无；接受 |
| 上游删了文件、本项目也删了 | 状态 `D`，需登记；若已登记则一致 | 无；这是正确行为 |
| 新增文件落在 `extensions/` | 不告警 | 正确：那正是扩展区 |
| submodule（`.codebuddy`）变更 | 被 `is_upstream_file` 排除，不登记 | 正确：它是独立仓库 |
| 锚点之后的上游新提交 | 完全看不见 | 同步前另行比对远端 |

## 什么时候该怀疑结论

- 输出「通过：0 个文件变更，N 条登记」但登记数是 0 → 锚点可能等于 `HEAD`，检查是否刚同步完。
- 输出大量 `[已失效]` → 先确认锚点没被 rebase 或误改，再动手删条目。
- 只跑过 `--changed` 就认为清单完整 → 不成立，`--changed` 覆盖不到已提交的未登记改动。
