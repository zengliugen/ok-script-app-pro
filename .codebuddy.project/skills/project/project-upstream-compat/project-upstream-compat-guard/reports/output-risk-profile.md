# 输出风险档案

技能：`project-upstream-compat-guard`

## 为什么需要这份档案

技能脚本的输出会被当作「是否合规」的判据使用。判据一旦误报或漏报，规则就失去可信度——
误报会让人习惯性忽略告警，漏报会让人误以为安全。这份档案列出最可能出错的地方与自检动作。

## 风险矩阵

| 风险 | 触发场景 | 影响 | 缓解措施 |
|---|---|---|---|
| 误报：把新增文件当改动 | 上游新增文件被本项目复制过来 | 噪音淹没真实问题 | 只对 `M`/`D` 做硬判定；`A` 仅在落入上游专属目录时告警 |
| 漏报：锚点选错 | `synced_upstream_commit` 滞后于实际 | 把已同步的改动当成未登记，或反之 | 校验前 `git cat-file -e` 断言锚点存在；同步后强制更新锚点 |
| 漏报：只查已提交 | 工作区改动未提交时跑全量模式 | 未提交的改动不被发现 | `--changed` 模式覆盖工作区；提交前建议跑一次 |
| 重命名判错 | 上游重命名文件 | 状态被误判为 `A` 而漏掉删除 | 重命名（`R`）归并为 `M` 处理 |
| 路径分隔符 | Windows 反斜杠 | 与 YAML 中的正斜杠不匹配 | 统一 `replace("\\", "/")` |
| 配置漂移 | 索引改结构 | 脚本读到错误路径 | 缺配置即退出码 3，不回退默认值 |
| 隐性依赖 | 系统无 PyYAML | 脚本直接崩 | 明确报错并提示 `pip install pyyaml` |

## 输出质量维度

| 维度 | 要求 |
|---|---|
| 可操作性 | 每条问题都指出具体路径与处置动作，不输出「有问题」这种空话 |
| 可判定性 | 退出码二值明确（0 通过 / 1 有问题），可被 CI 与其他脚本消费 |
| 不越权 | 只报告，不自动修改登记清单——自动补 reason 会造出无意义条目 |
| 信息密度 | 汇总行给出「变更数 / 登记数 / 问题数」，明细按标记分组 |

## 自检动作

交付前确认：

1. 每条 `[未登记]` 都带路径与状态，人能直接去补。
2. 每条 `[已失效]` 都提示「删除条目」而非「更新条目」。
3. 告警与硬性问题分开呈现，不混在同一列表里降低可读性。
4. 错误信息包含修复建议（「请检查 upstream 变更后更新 …」），不只有异常类型。
5. 不声称「通过 = 上游行为完好」——只声称「登记完整」。

## 审阅提示

在加深包体（新增脚本、评测、治理）之前重读这份档案一次；
在批准示例输出之前再重读一次。
