# 输出风险档案

技能：`upstream-compat-sync`

## 为什么需要这份档案

本技能会**改写 Git 历史**（master 前移、推送、必要时 force push），出错代价高于普通技能：
方向搞反会让 master 永久失去上游镜像语义，消息写错会把错误事实固化进历史。
这份档案列出最可能出错的地方与自检动作。

## 风险矩阵

| 风险 | 触发场景 | 影响 | 缓解措施 |
|---|---|---|---|
| **方向搞反** | 在 master 上 `git merge dev` | master 混入项目提交，不再能与上游快进 | `sync_guard.py check` 三项不变量；`git merge --ff-only` 强制快进 |
| 误判同步完成 | master 前移了但没合进 dev | 上游 bug 仍在，下次同步基线错位 | `check --stage after` 校验 dev 包含 master |
| 基准漏更新 | 忘记改 `synced_upstream_commit` | 后续差异校验以旧锚点比对，整体失真 | 同一项检查覆盖；脚本直接读 yaml 比对 |
| 冲突处置吞掉一边 | 用 `-X ours` / 整文件保留本地 | 静默丢弃上游改进 | SKILL.md 明令禁止；正文需写明每个冲突的理由 |
| 提交消息与事实不符 | 凭印象写上游改了什么 | 历史里留下假记录，误导后续排查 | 「摘要与正文的常见错误」表；正文写作前先跑 `git diff --name-status` 核对 |
| 测试结论混用 | 拿 `extensions_tests/` 通过当作上游兼容证据 | 上游行为被破坏却误判为安全 | 明确「结论不可互换」；`tests/` 单独判定 |
| 环境未更新误判为代码问题 | 框架大版本升级后 venv 仍旧 | 把 ImportError 当成代码 bug 去改 | 先比对 `pip show` 与 `requirements.txt`，不一致先重装 |
| 强推时覆盖他人提交 | 远程已被别人更新 | 丢失他人工作 | 一律 `--force-with-lease=<ref>:<期望原 sha>` |

## 输出质量维度

| 维度 | 要求 |
|---|---|
| 可判定性 | 退出码二值明确（0 通过 / 1 违反 / 3 环境不可用），可被 CI 消费 |
| 可操作性 | 每条问题指出具体分支关系与处置命令，不输出「方向不对」这种空话 |
| 不越权 | 只检查与报告，**不自动改写历史**——force push 必须由人确认 |
| 事实一致 | 提交正文里的每项声明都能用 `git diff` 复现，不写未核实的推测 |

## 自检动作

交付前确认：

1. 同步前的检查确实跑过且退出码为 0，而不是跳过。
2. 提交消息里每个「上游改了什么」都能用 `git diff <旧> <新>` 复现。
3. 提交消息没有出现「合并进 master」这类与方向约定矛盾的说法。
4. 大版本升级已写进摘要——这是最容易被漏、又最重要的一条信息。
5. 测试结论按测试根分别陈述，没有把扩展测试通过说成「上游行为完好」。
6. 若执行过 force push，已确认用的是 `--force-with-lease` 且带期望原 sha。

## 审阅提示

在新增检查项或放宽某条不变量之前重读一次——本技能的价值全在「拦住不报错的错误」，
放宽一条判据就等于少拦一类事故。
