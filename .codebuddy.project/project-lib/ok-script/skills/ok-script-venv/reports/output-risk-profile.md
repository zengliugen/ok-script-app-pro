# 输出风险画像（ok-script-venv）

## 风险矩阵

| 风险类别 | 严重度 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|---|
| 静默回退到系统 python | 高 | 中 | 缺 PySide6 等依赖，测试以 `ImportError` 失败，被误判为「代码坏了」 | 规则第 3 条要求回退必须**显式说明**；`references/shell-snippets.md` 单列「CI 与本地差异」 |
| 让用户依赖 `activate` | 中 | 高 | 子进程、IDE 运行配置、`pwsh -File` 拿不到环境，行为与交互式 shell 不一致 | 规则第 2 条明确「优先直接调用路径」；正文单列「为什么不建议 activate」对照表 |
| 相对路径按脚本位置解析 | 中 | 中 | 从别的目录调用时指向不存在的解释器 | 正文「路径基准陷阱」给出 `$PSScriptRoot` / `$MyInvocation` 的正确写法 |
| 在需要可靠的场景误用两级判断 | 高 | 中 | 覆盖率与自动化脚本用错环境，测试全部跳过仍返回成功 | 单列「与 python-env 的分工」并给出判据：脚本/CI/测试/覆盖率 → `python-env` |
| 直接调 `Scripts\` 下的可执行文件 | 低 | 中 | 依赖 `PATH`，在任意工作目录下可能找到另一个同名工具 | 统一推荐 `-m <模块>` 写法，正文说明理由 |

## 与其他技能的边界风险

本技能与 `python-env` 是唯一有实质重叠的邻居，越界表现与处置：

| 越界形态 | 表现 | 处置 |
|---|---|---|
| 本技能自行实现四级探测 | 与 `python-env` 分叉，两处结论不一致时无从判断 | 明确本技能只做两级判断（本地 → 全局）；需要 `import ok` 校验时导流到 `python-env` |
| `python-env` 顺带给出日常命令示例 | 同一命令出现两种写法 | `python-env` 只输出绝对路径，命令写法归本技能 |
| 顺手创建或重建环境 | 与 `python-env` 的 `ensure` 冲突，且工具环境规格只在引擎包里维护 | 一律导流 `python-env ensure` |
| 顺手跑 ruff 或覆盖率 | 绕过 `python-lint` / `python-test-coverage` 的口径 | 只给出命令里的解释器部分，检查本身交对应技能 |

## 输出质量维度

### 命令可直接执行

- 给出的片段必须能**原样粘贴**就工作，不依赖用户先把某个变量设成特定值。
- PowerShell 与 POSIX 分开给，不混写。

### 风险提示到位

- 回退到全局 `python` 时必须说明后果，不能静默处理。
- 用户提到 CI 或测试时必须提示：这两类场景应改用 `python-env`。

## 已知局限性

1. **不校验解释器装了什么**：只判断路径存在。用错环境（存在但缺依赖）时本技能发现不了，症状是 `ImportError`。
2. **路径基准受工作目录影响**：相对路径写法在换目录调用时会失效，需要改用脚本自身位置推导的绝对路径。
3. **不覆盖其他环境管理器**：conda、poetry、pdm 的布局不同，本项目的约定是统一 `.venv`。
4. **无脚本自动化**：全部结论靠判断路径存在，没有可执行脚本做兜底校验。
5. **来源会演进**：上游 `.agents/skills/use-local-venv` 更新时需按 `CHANGELOG.md` 的同步策略手工比对。
