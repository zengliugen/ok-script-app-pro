## 2026-11-12 从 .agents 迁移并中文化

**为什么迁**：`.agents/skills/` 那套约定不参与本项目的引擎校验，兄弟技能早已迁到项目侧；
只剩本技能与 `initialize-ok-script-app` 留在原处，形成两套并行组织方式。

**本地改造**：

1. 正文中文化，并按引擎技能规范补齐核心契约、参考文献、不适用范围、已知局限四节。
2. **新增「与 python-env 的分工」一节**。这是迁移时最容易踩的冲突点：项目侧包里已有
   `python-env` 技能，它同样涉及「用哪个解释器」。经核对，两者层次不同，不构成重复：

   | 维度 | `python-env` | 本技能 |
   |---|---|---|
   | 层次 | 机制层 | 约定层 |
   | 探测 | 四级，每级校验 `import ok` | 两级，只看路径存在 |
   | 服务对象 | 测试/覆盖率必须跑在应用环境、CI 与脚本需要可靠路径 | 日常手敲命令 |

   因此不合并，而是在正文与 README 各写一次分工表，并给出选用判据：
   一次性手敲 → 本技能；要写进脚本或 CI、或涉及测试与覆盖率 → `python-env`。

3. **补入三处来源没有的内容**：路径基准陷阱（相对路径以工作目录为基准，不是脚本位置）、
   CI 与本地差异（CI 没有 `.venv`，回退分支必须存在且要显式说明）、
   为什么统一用 `-m <模块>` 而不是直接调 `Scripts\` 下的可执行文件。

**未采纳来源的部分**：来源的 `& $Python .agent/skills/github_issue_solver/scripts/github_api.py`
示例属其他仓库的场景，与本项目无关，未保留。
